1단계Rule·Skill 초안 직접 작성

폴더와 파일을 만들고, 아래 내용을 붙여 넣으세요

이 단계는 참가자가 파일 탐색기와 편집기에서 직접 진행합니다. Rule에는 공통 원칙 네 항목을, Skill에는 업무 절차 세 단계를 저장합니다. 자세한 분석 기준과 결과물 구성은 2단계에서 추가합니다.

  1. 실습 폴더 최상위에 .bob 폴더를 만듭니다.

    왼쪽 파일 탐색기에서 새 폴더를 만드세요. data/와 같은 위치이며, 이름 앞의 점(.)도 포함합니다.

  2. .bob 안에 하위 폴더를 만듭니다.

    rules와 skills를 만들고, skills 안에 ops-analysis를 만듭니다. 이미 있는 폴더는 그대로 사용하세요.

  3. 두 Markdown 파일을 만들고 내용을 저장합니다.

    rules에는 project-rules.md, skills/ops-analysis에는 SKILL.md를 만듭니다. 아래에서 각 내용을 복사해 해당 파일에 붙여 넣고 Ctrl+S 또는 ⌘S로 저장하세요.

완성할 폴더 구조

실습 폴더/
├── data/
└── .bob/
    ├── rules/
    │   └── project-rules.md
    └── skills/
        └── ops-analysis/
            └── SKILL.md

같은 파일이 이미 있다면 아래 초안으로 내용을 정리하세요. SKILL.md의 대문자와 .md 확장자를 확인하세요.

1. Rule 초안 (project-rules.md)

.bob/rules/project-rules.md

2. Skill 초안 (SKILL.md)

.bob/skills/ops-analysis/SKILL.md

1단계 완료 확인

  • 위 경로에 두 파일을 만들고 저장했습니다.
  • Rule에는 공통 원칙 네 항목, Skill에는 이름·설명과 절차 세 단계가 들어 있습니다.
  • Skill 파일 맨 위의 ---와 name: ops-analysis가 포함돼 있습니다.

두 파일을 저장했으면 2단계로 이동하세요. Bob에게 초안 작성을 맡기는 대체 방법은 아래 참고 섹션에서 볼 수 있습니다.

2단계기존 Rule·Skill 업데이트

분석 기준과 생성할 분량을 구체화합니다

두 파일을 저장한 뒤 새 Bob 대화에서 아래 요청을 보냅니다. 직접 만든 짧은 초안에 비교 기준, 보고서의 네 행 표, 선그래프 형태, 생성할 파일의 범위를 추가하게 합니다.

  1. 2단계 요청문을 전송합니다.

    정상 비교·인과 판단과 함께 보고서 분량, 선그래프 한 개, 보조 파일 생성 금지를 기존 지침에 반영하게 합니다.

  2. 수정된 내용과 차이 세 가지를 확인합니다.

    채팅의 설명과 실제 파일을 함께 봅니다. Rule은 공통 판단·표현 원칙으로, Skill은 수행 절차로 보강됐는지 확인하세요.

2단계 완료 확인

  • 보고서는 요약 두 문장·비교표 네 행·짧은 판단으로 한정됩니다.
  • 그래프는 시간별 API p95 선과 핵심 구간 음영 하나입니다.
  • 분석·검증·HTML 생성용 보조 프로그램 파일 금지가 추가됐습니다.
  • Bob이 추가한 기준 세 가지를 설명했습니다.

여기까지는 지침 개선입니다. 실제 분석과 결과물 생성은 다음 단계에서 진행합니다.

2단계 요청문

Bob 채팅에 붙여 넣는 요청

3단계개선한 지침을 실제 업무에 적용

Skill을 호출해 분석과 보고를 수행합니다

지침 파일의 저장을 확인한 뒤 새 대화를 엽니다. “앞에서 만든 기준으로 이 문제를 풀어 주세요”라고 요청하는 단계입니다.

  1. Skill이 인식되는지 확인합니다.

    Bob 설정의 Skills 탭에서 프로젝트 Skill ops-analysis를 찾습니다. 1단계에서 직접 저장한 파일의 name과 같은지 확인하세요.

  2. 새 대화에 3단계 요청을 전송합니다.

    Rule은 적용하고 Skill은 실제로 활성화해 작업하게 합니다. 승인 카드가 표시되면 이름을 확인하고, 자동 승인 상태라면 호출·활성화 기록을 확인합니다.

  3. 생성된 두 결과물을 엽니다.

    outputs/의 보고서 한 개와 HTML 한 개를 확인합니다. 보고서는 비교표 네 행, 대시보드는 API p95 선그래프 한 개가 핵심입니다.

결과를 볼 때 질문할 것

  • 네 행 비교표로 지연과 API 영향을 파악할 수 있나요?
  • 시간별 API p95 선과 배치 구간 음영을 쉽게 읽을 수 있나요?
  • 유력 가설·미확정 사항·다음 확인 두 개가 짧게 보이나요?
  • 새 보조 프로그램이나 숨겨진 상세 패널이 추가되지 않았나요?

진행 중 헷갈리면 확인하세요

2단계에서 Bob이 먼저 분석하거나 보고서를 만듭니다

현재 단계는 Rule·Skill 수정이라고 알려 주세요. 지침 파일과 변경 설명을 확인한 뒤 3단계에서 실제 분석을 요청합니다.

Skill이 목록에 없거나 실제로 호출하지 않습니다

프로젝트 폴더와 .bob/skills/이름/SKILL.md 경로를 확인하고, 파일 앞부분의 name·description이 있는지 봅니다. 파일 내용을 읽은 것과 Skill을 실제로 활성화한 것은 구분합니다. 인식되지 않으면 진행자에게 현재 화면과 파일 경로를 알려 주세요.

이전 3단계가 실행 중이거나 보조 프로그램 파일이 또 생깁니다

기존 대화에 로드된 지침은 파일을 수정해도 현재 작업에 자동 반영되지 않을 수 있습니다. 기존 실행을 중지하고 2단계 지침의 저장을 확인한 뒤 새 대화에서 3단계를 시작하세요. 새 지침은 기존 보조 스크립트 재사용도 금지합니다.

생성된 보고서나 대시보드가 너무 길거나 수치가 의심스럽습니다

보고서 표 네 행, KPI 세 개, 선그래프 한 개와 음영 한 개라는 전체 생성 한도를 확인하세요. 접힌 상세 패널도 만들지 않습니다. 불명확한 값은 집계 구간·계산 방법을 다시 확인하게 합니다.

복사 버튼이 작동하지 않습니다

‘전체 선택’을 누르고 Ctrl+C 또는 ⌘C로 복사하세요. 입력란의 보이는 부분뿐 아니라 전체 내용을 가져갈 수 있습니다. 1단계의 Markdown은 해당 파일에, 2·3단계의 요청문은 Bob 채팅에 붙여 넣습니다.

1단계의 Markdown과 2·3단계 요청문, 참고 요청문은 프롬프트.md에서도 볼 수 있습니다. 기존 결과물이 있다면 이번 실행으로 생성·갱신한 결과를 확인하세요.
