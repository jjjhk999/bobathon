Db2 전용 모드와 프로젝트 규칙을 만듭니다. 진행자와 함께 결제 조회 SQL을 개선한 뒤, 각자 야간 배치 SQL을 튜닝하고 Db2 조회 시간을 비교합니다.

  2. 진행자가 배포한 최신 db2-sql-lab.zip을 풀고 Bob IDE에서 db2-sql-lab 폴더를 엽니다.

Bob에서 실제 Db2 조회하기

실습 폴더에는 Db2 MCP 서버 db2-sql-lab 연결이 미리 설정되어 있습니다. Bob에게 SQL 실행을 요청하고 승인하면, Bob이 run_query 도구를 호출합니다. 이 도구가 실제 실습용 Db2에서 SQL을 실행하면 Bob이 결과 미리보기와 실행 시간을 채팅에 보여줍니다.

run_query는 데이터를 읽는 SELECT 조회만 실행합니다.

-- Daily approved payments per active Seoul merchant.
-- The legacy report compares export-formatted merchant IDs and payment dates,
-- then performs separate lookups for count and amount within the weekly extract.
SELECT
    M.MERCHANT_ID,
    M.MERCHANT_NAME,
    (
        SELECT COUNT(*)
        FROM BOB_SQL_LAB.PAYMENT P
        WHERE TRIM(CHAR(P.MERCHANT_ID)) = TRIM(CHAR(M.MERCHANT_ID))
          AND P.PAYMENT_STATUS = 'APPROVED'
          AND P.PAYMENT_TS >= TIMESTAMP('2026-10-12-00.00.00')
          AND P.PAYMENT_TS < TIMESTAMP('2026-10-19-00.00.00')
          AND VARCHAR_FORMAT(P.PAYMENT_TS, 'YYYY-MM-DD') = '2026-10-15'
    ) AS APPROVED_COUNT,
    DECIMAL(COALESCE(
        (
            SELECT SUM(P.AMOUNT)
            FROM BOB_SQL_LAB.PAYMENT P
            WHERE TRIM(CHAR(P.MERCHANT_ID)) = TRIM(CHAR(M.MERCHANT_ID))
              AND P.PAYMENT_STATUS = 'APPROVED'
              AND P.PAYMENT_TS >= TIMESTAMP('2026-10-12-00.00.00')
          AND P.PAYMENT_TS < TIMESTAMP('2026-10-19-00.00.00')
          AND VARCHAR_FORMAT(P.PAYMENT_TS, 'YYYY-MM-DD') = '2026-10-15'
        ), 0
    ), 18, 2) AS APPROVED_TOTAL
FROM BOB_SQL_LAB.MERCHANT M
WHERE M.REGION = 'SEOUL' AND M.ACTIVE_YN = 'Y'
ORDER BY M.MERCHANT_ID;

제때 끝나지 않은 야간 작업 찾기

아침에 출근해서 밤사이 자동으로 돌아간 작업을 점검합니다. 2026년 10월 1일부터 7일까지, 야간 작업 1~100번 중 날짜별로 어떤 작업이 마감 시간까지 성공하지 못했나요?

날짜와 작업 번호로 두 표를 연결합니다. 1번은 일정만 있고, 7번은 일정 하나에 시도가 두 번 있습니다. 7번은 재시도에서 04:05에 성공했으므로 마감인 04:00을 넘겼습니다.

원본 SQL 보기 queries/challenge2-baseline.sql 
-- Legacy batch SLA report from a business-date and job-ID text extract.
-- This legacy report treats integer job IDs as text patterns within each date.
-- Report operations group 1 (job IDs 1–100) for business dates 2026-10-01 through 2026-10-07.
-- ATTEMPT_COUNT includes every attempt. FAILED_ATTEMPT_COUNT counts FAILED only.
-- A success at DEADLINE_TS is on time. Omit on-time entries.
WITH RUN_SUMMARY AS (
    SELECT
        S.BUSINESS_DATE,
        S.JOB_ID,
        S.JOB_NAME,
        S.DEADLINE_TS,
        (
            SELECT COUNT(*)
            FROM BOB_SQL_LAB.BATCH_RUN R
            WHERE TRIM(CHAR(R.JOB_ID)) LIKE TRIM(CHAR(S.JOB_ID))
              AND R.BUSINESS_DATE = S.BUSINESS_DATE
        ) AS ATTEMPT_COUNT,
        (
            SELECT COUNT(*)
            FROM BOB_SQL_LAB.BATCH_RUN R
            WHERE TRIM(CHAR(R.JOB_ID)) LIKE TRIM(CHAR(S.JOB_ID))
              AND R.BUSINESS_DATE = S.BUSINESS_DATE
              AND R.RUN_STATUS = 'FAILED'
        ) AS FAILED_ATTEMPT_COUNT,
        (
            SELECT MIN(R.END_TS)
            FROM BOB_SQL_LAB.BATCH_RUN R
            WHERE TRIM(CHAR(R.JOB_ID)) LIKE TRIM(CHAR(S.JOB_ID))
              AND R.BUSINESS_DATE = S.BUSINESS_DATE
              AND R.RUN_STATUS = 'SUCCESS'
        ) AS FIRST_SUCCESS_TS
    FROM BOB_SQL_LAB.BATCH_SCHEDULE S
    WHERE S.BUSINESS_DATE >= DATE('2026-10-01')
      AND S.BUSINESS_DATE < DATE('2026-10-08')
      AND S.JOB_ID BETWEEN 1 AND 100
)
SELECT
    BUSINESS_DATE,
    JOB_ID,
    JOB_NAME,
    DEADLINE_TS,
    ATTEMPT_COUNT,
    FAILED_ATTEMPT_COUNT,
    FIRST_SUCCESS_TS,
    CASE
        WHEN ATTEMPT_COUNT = 0 THEN 'MISSED'
        WHEN FIRST_SUCCESS_TS IS NULL THEN 'NO_SUCCESS'
        ELSE 'LATE'
    END AS SLA_STATUS
FROM RUN_SUMMARY
WHERE FIRST_SUCCESS_TS IS NULL OR FIRST_SUCCESS_TS > DEADLINE_TS
ORDER BY BUSINESS_DATE, JOB_ID;

느릴 수 있는 이유 · 일정마다 시도 횟수, 실패 횟수, 첫 성공 시각을 구하는 세 조회가 같은 실행 이력을 반복해서 읽습니다. 숫자인 작업 ID를 문자열로 바꿔 LIKE로 비교하는 조건도 인덱스 활용을 어렵게 할 수 있습니다.

도전 목표 · 원본과 같은 결과를 유지하면서 0.10초(100ms) 이내를 시도합니다. 참가자가 동시에 조회하고 있다면, 같은 시간대에 잰 본인의 원본 대비 70% 이상 단축을 목표로 삼으세요.
